# Standards

Repo conventions. Environment, gate commands and machine facts: see `docs/environment.md`. Structure and decisions: see `docs/architecture.md`.

## Shell (`install.sh`, `lib/`, `scripts/`, `dashboard/hook.sh`)
- `#!/usr/bin/env bash` and `set -euo pipefail`.
- Each file starts with a usage header (comment).
- Messages and comments in English.
- Log with `log`, `warn`, `ok` and `die` (ANSI color, to stderr): `install.sh:85-87`.
- Control variables in UPPERCASE (`DO_*`); locals in lowercase.
- Compatible with macOS bash 3.2: no `mapfile`, `declare -A` or `${v,,}`. Tests pass on 3.2.57 and CI runs on ubuntu and macos. As an explicit rule, it is inferred (to be confirmed).
- `.shellcheckrc` disables SC2034, SC1090 and SC1091 (dynamic variables and `source`).
- A new `.sh` must be added to the shellcheck list in `.github/workflows/ci.yml` (by hand).

## Node in the dashboard (`dashboard/`)
- ESM `.mjs` modules, HTTP server with no npm dependencies (`dashboard/server.mjs`).
- No build: what is in `dashboard/` is what runs (`.html` pages served as they are; to be confirmed).
- Claude Code hooks: `dashboard/hook.sh` and `dashboard/hook.mjs`.
- Usage details: `docs/dashboard.md`.
- Do not add an npm dependency without a change that asks for it.

## Templates (`templates/`)
- `lib/render.sh` syntax (awk engine): `{{VAR}}`, `{{#if}}`, `{{#unless}}`, `{{else}}`. Variables come from the environment (the loaded conf).
- Generated files (agents, rendered skills, `project-context.md`) end with `<!-- ai-team:generated cksum=N -->`.
  - Edit the **template** or `.claude/ai-team.conf` and run `install.sh --render`; do not edit the generated file.
  - A generated file edited by hand is only overwritten with `--force`.
- `project-context.md`: above `<!-- ai-team:notes -->` is regenerated; below is preserved (`install.sh:298-309`).
- Copied skills (team, onboarding, grilling, grill-me) and the dashboard have no cksum and are not overwritten without `--force`.
- `templates/skills/worktree/wt.sh` is copied without rendering.

## Tests
- `tests/run.sh` (detector, render, installer): no framework. Write `t "description" 'condition'` (`tests/run.sh:23`); the condition is a string evaluated with `eval`. Helpers: `detect`, `inst`, `has`.
- Runs under `set -uo pipefail`, without `-e`: one failing test does not abort the next ones.
- Fixtures generated by `tests/fixtures.sh`; do not commit sample projects.
- Isolate in temporary directories: hub, token and notify. Use a fake npm so OpenSpec is not really installed.
- Dashboard: `tests/*.test.mjs`, one per module.
- Run everything: `make test` (124 tests today). There is no per-section filter in `tests/run.sh`.
- Behavior changed: new or adjusted test in the same commit.

## Commits and branches
- Conventional Commits in English with a scope: `feat(install)`, `fix(dashboard)`, `refactor`, `chore`, `docs`.
- Topic branches: `feat/*`, `fix/*`, `chore/*`, `docs/*`, `refactor/*`.
- Flow: topic, `staging`, PR to `main`. `main` is the version that curl installs.
- CI runs on push to `main` and on PRs, not on push to `staging`.

## PR checklist
- [ ] `make test` green.
- [ ] shellcheck with no warnings (command in `docs/environment.md`).
- [ ] New `.sh` in the shellcheck list in `.github/workflows/ci.yml`.
- [ ] README and `docs/` updated when behavior changes.
- [ ] Derived files regenerated (`--render`) if a template changed, without editing the generated file by hand.
